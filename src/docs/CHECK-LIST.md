# Чек-лист проекта

Здесь вы найдёте обязательные требования к проекту. Проверьте, что работа соответствует всем пунктам ниже, прежде чем сдавать её на ревью.

## Стиль написания кода

- Весь код отформатирован с помощью Prettier.
- Все импорты отсортированы.
- Все HTML-атрибуты отсортированы.
- В проекте настроен ESLint, и он не возвращает никаких ошибок.
- Все переменные в проекте написаны в CamelCase и отражают смысл содержимого.
- Все типы в проекте названы единообразно и вынесены в отдельный файл.
- При необходимости типы разделены на отдельные файлы по каждому модулю.
- Git-коммиты должны быть осмысленными и соответствовать правилам наименования.
- У репозитория с проектом есть оформленное README.md.
- Комментарии в коде должны быть осмысленными и использоваться только в случае, если невозможно описать поведение названиями переменных и функций.
- Удалены все `console.log`, `alert` и `debugger`, которые использовались во время отладки.
- В проекте нет закомментированного кода.
- Нет inline-стилей, не использовано правило `!important`.
- В коде, комментариях или названиях коммитов нет смайлов или эмодзи.
- Вёрстка не имеет семантических ошибок. Для элементов используются соответствующие теги. Например, все ссылки должны быть оформлены через `<a/>`, а все формы — через `<form/>` и т. п.
- Код проекта не вызывает ошибок и предупреждений в консоли браузера.

## Требования к реализованному решению

- Код проекта выложен на GitHub.
- Весь проект написан на TypeScript.
- Для реализации проекта использованы библиотеки React, Redux Toolkit, React Router.
- Вёрстка полностью адаптирована под все размеры экранов начиная с 320px и далее (>4K) и не имеет заметных багов.

### Валидация форм

- Во всех формах есть валидация:
  - Все обязательные поля обозначены звёздочкой `*` в конце лейбла поля.
  - При отправке формы поля ввода, в которых возникла ошибка валидации, обозначаются красным бордером, и под полем пишется сообщение об ошибке, которое относится к текущему полю.
- В проекте настроено unit-тестирование и написаны тесты с использованием Jest.
- Для форм рекомендуется использовать `react-hook-form` и `zod` (или эквивалентную схему-валидацию), чтобы правила были в одном месте и их было проще тестировать.
